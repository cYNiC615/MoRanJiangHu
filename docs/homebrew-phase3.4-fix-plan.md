# Homebrew Phase 3.4 Fix Plan

> 日期：2026-06-21
> 本文是 Phase 3.4 当前修复队列。已完成项只保留结果记录；详细状态见 `docs/homebrew-phase3-implementation-status.md`。

## 边界

- 不改 Prompt 协议标签名。
- 不恢复旧武侠/仙侠默认体验。
- 不把本轮变成新功能迭代。
- 不主动改存档结构，除非修复明确需要且兼容读取。
- 不做浏览器自动化 UI 测试；需要 UI smoke 时只启动本地服务器，由玩家手动测。

## 已完成记录

- 现代默认链路已收口：主剧情/开局/变量/文章优化/COT/format/runtime 文案清理旧武侠、修炼、门派、古风小说和固定现代道具清单锚点；默认难度摘要改为现代风险、资源和日常压力口径，关闭饱腹口渴系统时不输出 `diff_phys_*`。
- 世界观链路已统一：初始世界生成接入导演偏好和未转正角色种子弱约束；输出契约统一为 `<世界观>` / `<世界基底>`；`core_world_summary` 写入后主剧情默认读取摘要，摘要缺失才回退完整世界观；摘要提示优先保留本局独特组织、长期冲突、禁忌、稀缺资源和地理社会结构。
- Context / diagnostics 已补强：主剧情 assembly 同源化，字数、人称、重试、免责声明去重；payload 诊断记录 Tavern 分支、message 结构、provider protocol、`worldPromptSource`、`nsfwPromptLevel`、`suppressedWorldbookCount` 等结构摘要。
- NSFW 注入已分层：runtime extra prompt 使用 `disabled / beacon / intimacy / explicit`，普通日常只保留轻信标，非 explicit 层压制完整名器/显式身体世界书；主要角色私密/名器建档补齐保留，但普通日常不再因 NSFW 总开关反复补私密、名器、子宫档案。
- 第 0 回合角色种子已对齐主链：开局原生消息链、Tavern worldbook extra 和开局变量生成 extra prompt 均注入题材模式、玩家剧情倾向和导演配置；主剧情/女主/开局 COT 均要求优先匹配可用角色种子并保留精确 `角色种子ID`。
- 变量生成链路已去重并现代化：取消本地手动 `variable_calibration` 世界书附加；变量模型统一读取正文与 `<变量规划>` 做世界书匹配；旧坐标路径不再进入变量路径登记表；变量承接、变量模型、变量 COT、NPC 数值协议、变量校准参考、女性姓名提示和行动选项示例已清理旧题材示例。
- 开局和 UI smoke 项已落地：右侧功能页直接弹窗、新游戏第六步顶部可见且可滚动由玩家手动确认通过；角色种子 UI 已把 `红颜/后宫对象` 改为枚举入口；开局配置和新建档确认摘要使用题材化切入文案。
- 地图相关已低频化和现代化：现代地图 prompt 清理旧武侠母板，现代世界基底默认根改为 `现实世界`，孤立空 `诸天万界` 根兼容清理，非空旧地图不自动删除。
- 普通现代随身物和首条任务已收口：普通手机、校园卡、钱包、银行卡、钥匙、笔记本电脑和普通衣物默认只作生活背景/身份凭证/操作入口；现代首条主线必须是一周内可完成或阶段性推进的短周期任务，学期级/毕业级目标只能作背景或后续规划。
- 社交命令兼容已修：字符串化 JSON 的 `push 社交` 可还原为对象；非对象、数组、无姓名整对象不会生成 `角色N`；NPC 姓名字段兼容 `姓名 / 名字 / 名称 / name`；有姓名的整对象 `push 社交 = {...}` 不再要求同回合正文出现，突兀 NPC 交由玩家在社交面板删除。
- 任务奖励兼容已修：`奖励描述` 统一归一为可渲染 `string[]`，`{类型, 内容}` 转安全文本；奖励结算复用同一归一化逻辑，TaskModal 保留轻量兜底，不再把对象作为 React child 渲染。
- 手动 smoke 已确认覆盖：初始世界生成不带旧武侠地图模板、旧成长字段和输出标签冲突；开局规划普通日常不常驻完整名器类世界书；主剧情 diagnostics 能区分非 Tavern 分支。

## 未完成队列

1. 地图摘要后续方案
   - 本轮不实现地图摘要；后续 Phase 重构地图功能时，再从六层地图树生成确定性结构摘要。
   - 摘要应突出当前大/中/小/区/子地点的独特关系、核心地点、边界和可拼接信息，避免在不了解外部地图时把当前地图硬拼成复杂大地图。

2. 普通现代钥匙物品化观察
   - 新 smoke 中 `<变量规划>` 曾把 `宿舍钥匙/老式公寓六楼隔间与楼下单元门钥匙` 写成 `Item000` 任务道具。当前变量提示已要求普通钥匙只作为生活背景/身份凭证/操作入口，不因 `<变量规划>` 写成任务道具就落库；本轮暂不继续加规则。
   - 若后续多轮仍把宿舍钥匙、校园卡、手机等普通现代物件写入背包，再回头检查开局变量规划生成端是否需要同步弱化普通物件物品化倾向。

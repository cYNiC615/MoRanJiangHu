# 场外角色对话设计草案

状态：已完成上游方案评估；本轮不接入运行时，作为独立功能实施。先做单聊，群聊后置。

## 首个实现范围

- 对象仅限当前存档内已建档 NPC；复用社交人物入口、现有本地 API 配置和日志显示。
- 单聊默认使用主剧情模型；仅在用户显式配置时使用独立模型，不增加必填配置。
- 角色上下文只包含本人档案/亲身记忆、当前可见环境、明确在场人物的公开信息，以及有证据表明本人知情的近期经历。
- 未引入角色种子完整卡、其他 NPC 私密记忆、隐藏剧情规划和全局状态快照不进入角色视角。

## 状态语义

- 场外回复先作为待纳入对话保存。对话本身不推进游戏时间，不直接修改好感、任务、背包或其他正式变量。
- 模型返回纯对话内容；任何命令/协议文本都不能从该入口执行。
- 玩家下一次主回合行动提交时，冻结本次待纳入记录 ID 列表，将原始发言纳入主剧情上下文，由正常变量链路结算。
- 主回合完整成功落盘后，只确认本次冻结的记录；提交期间新产生的对话不得被一起清空。
- 失败、取消、重试保留待纳入记录；回档恢复对应对话状态，避免重复生效或丢失。
- 对话按存档谱系/人物 ID 隔离，纳入本地保存和导出；不以名字作为唯一标识，不跨存档复用。
- 玩家可以丢弃未纳入对话；已纳入的内容只通过既有回档语义改变。

## 验证边界

- 非在场事件、其他人物私密档案和未来角色种子不得泄露到角色模型请求。
- 取消/失败/重新生成不执行状态命令；同一记录不会因重试重复纳入。
- 并发提交只确认冻结记录，读档和切换人物不会串会话。
- 聚焦真实请求载荷、提交原子性和本地存储行为，不为对话提示词措辞增加快照测试。

## 后续群聊

- 单聊的数据隔离和提交路径稳定后，再加入有界参与者集合、逐角色认知和轮次调度。
- 不直接搬入上游整套群聊 UI、多人轮流生成、移动端入口或新增公网服务。

# Homebrew Phase 3.2 Modern Urban Decisions

> 日期：2026-06-20
>
> 本文只记录仍会约束后续实现的决策。已经完整落地的实现细节不在这里展开；
> 当前实现状态和后续阶段见
> `docs/homebrew-phase3-implementation-status.md`。

## Phase 3.2 边界

Phase 3.2 直接承接 Phase 3.1 第一轮现代都市默认化，不再拆成 3.1.x。Phase 3
后续工作按 `3.2 -> 3.3 -> 3.4` 收口，不再继续扩张新的大功能。

- 只优化默认路径：没有显式选择题材、模式包、世界书或手写覆盖时，默认体验应是现代都市。
- 用户覆盖层优先：玩家手写世界观、玩家剧情倾向、PromptManager 覆盖、本地世界书和本地模式包不做隐式现代都市转换。
- 不要求旧武侠/仙侠存档兼容；但旧题材入口、本地模式包机制和用户数据不因本轮被删除。
- 不做全仓古风字符串清零；只改默认现代路径和玩家实际会碰到的活跃 copy。
- 不一次性重写 `B-full` 社交数据库、全 UI 或存档调用面；允许用兼容式 v2 子档案继续迁移长期关系语义。
- 不新建平行任务系统，不为了改名重写 schema。

## Phase 3 收口分段

- Phase 3.2：已收口当前 runtime/director/seeds 分支，并完成后处理调度最小本地规则。
- Phase 3.3：做角色种子和社交 v2 / 红颜规划完整闭环，达到玩法承接上的 B-full 体验；不做社交数据库拆分。
- Phase 3.4：用户手动 smoke、查漏补缺、文档 closeout、必要提交/推送和记忆更新。

Phase 3 的“做完”不包含导演配置导入导出、跨存档角色模板库、完整 `useGame.ts`
controller 拆分、全仓古风字符串清零或完整新社交数据库。

## 默认题材与模式

- 未明确选择题材时，运行时默认按 `现代都市` 处理。
- 显式选择武侠、仙侠等旧题材时仍尊重选择。
- “现代都市”不作为玩家必须主动选择的默认模式包展示；底层 profile 和模式世界书可以作为默认 fallback 存在。
- 世界规模玩家可见名采用：
  - `弹丸之地` -> `大学城`：一所大学、企业社区或大型机构支撑的小城镇。
  - `九州宏大` -> `都市圈`：一整座城市，多学校、多企业、多阶层和多组织并存。
  - `无尽位面` -> `跨城网络`：跨城关系、资本链、媒体网络和异地项目。
- 默认不带玄幻、修炼、境界、灵气、觉醒或低魔能力。
- 默认主调是校园、青年、兼职、实习、合租、家庭压力、社交圈和情感推进；灰色现实可以出现，但不是默认核心。

## 组织、势力与物品

- `玩家组织` 作为兼容容器保留，但默认开局不把组织当作主支点。
- `开局生成组织`、成员生成和初始伙伴默认关闭。
- 学校、公司、社团、家庭企业、秘密组织等可以由玩家世界观或剧情事实自然生成。
- `世界.势力列表` 在现代都市默认路径下应证据驱动；没有明确组织行动或势力结构时可以为空。
- 不为了补齐变量树强行生成势力互动历史。
- 手机、钱包、银行卡、普通衣物、普通钥匙等常识物品不默认物品化；只有独特、剧情相关、需要追踪或有机制影响的物品才进入背包。

## Prompt 主链

- Prompt 和协议内部继续使用“女主 / 女主剧情规划”，避免模型、parser 和字段语义混乱。
- 前端玩家可见入口使用 `红颜录`、`红颜规划`。
- 主剧情负责当回合正文、角色反应和局部结果；不在主剧情里承担长期大纲、任务方案、女主事件池或世界演变命令。
- 默认剧情骨架采用“轻量章节罗盘 + 开放探索 + 主线牵引”，复用现有 `剧情.当前章节`、`剧情规划` 和 `任务列表`，不新增章节 schema。
- 前台 `任务列表` 中 `类型=主线` 的任务承担玩家可见方向感。主线任务应有阶段推进、阻力、变化空间和完成判定，常态 2-4 个阶段目标，并至少包含 2 类具体锚点。
- 不默认生成支线、传闻、悬赏、组织任务、联系人名单或候选女主池。
- 默认开局可以是主角独处。只有故事事实、玩家输入、世界观或角色种子自然需要时才引入女性重要角色。

## 玩家剧情倾向

- `玩家剧情倾向` 是存档级导演偏好，不是世界母本事实。
- 它不合入 `world_prompt`，不直接覆盖已发生事实，不保存多版本历史或权重衰减。
- 优先级原则：已发生事实 > 玩家手写设定/剧情倾向 > 当前主线/章节罗盘 > 默认现代都市倾向 > 通用 prompt 偏好。
- 当前字段暂可落在 `OpeningConfig.玩家剧情倾向`；如果 Phase 3.2 新增导演配置块，可以迁移并保留旧字段读取兼容。

## 后处理调度

- 主剧情可以输出 `<后处理信号>`，只标记本回合是否值得规划分析或世界演变继续消化。
- `<后处理信号>` 不进入玩家可见历史、长期记忆或长期状态；raw/debug 文本可以保留。
- 解析缺失或失败时应保留安全兜底；如果信号可靠且判断不需要后处理，则本地是否还要强制触发由 Phase 3.2 的本地规则决定。
- 本地规则候选：主线缺失、主线完成/失效、玩家意图明显转向、新主要角色成立、关系突破或冲突升级、时间/地点大跨度切换、重大事件发生。

## B-lite / B-full 与红颜规划

- Phase 3.2 已开始 `B-lite` 和兼容式 `B-full` 起步迁移；Phase 3.3 负责把它做成完整玩法闭环。
- 边界是“在现有 `社交[]` 内引入 versioned 子档案”，不是拆成独立社交数据库。
- `B-lite` 目标是给重要女性角色补足可被变量生成、规划分析和女主规划读取的轻量行为字段。
- 行为字段应服务“人格内因 -> 当前 agenda -> 交流风格 -> 吸引/戒备/边界 -> 亲密阻力 -> 后宫兼容路径”这类可演绎信息。
- 女主规划 v2 读取已登场且确有承接价值的女性重要角色；没有可读内容或没有待处理更新时不生成空规划。
- 避免双写：稳定人格和行为内因尽量落在社交/NPC 档案，事件阶段、镜头条件和推进节奏落在 `女主剧情规划`。
- 变量生成可以补齐缺失行为字段，但不应覆盖已经稳定的人格、边界、硬锁或长期关系内因。

## 角色种子池

- 角色种子池是玩家预设“未来希望剧情中自然出现的女性角色素材”，不是开局伙伴、不是已成立关系、不是 `社交[]` 档案。
- 首版只支持女性角色种子；默认可发展为红颜/后宫对象。
- 未登场角色种子不写入 `world_prompt`、`剧情规划`、`女主剧情规划` 或 `社交[]` 作为既定事实。
- 种子定义和运行时状态分开。运行时状态至少能表达 `未引入 / 已引入 / 已转正`，并在转正后记录轻量 `linkedNpcId / linkedNpcName` 以防重复。
- 注入策略采用“入口摘要常驻，完整种子触发式展开”：常态只给入口摘要；当前场景、玩家行动、规划或后处理命中相关入口时，再展开 1-3 张相关种子。
- 第 0 回合允许自然使用角色种子，但不强制生成。
- Phase 3.3 的完成标准是新建/游戏内编辑、暂停/删除、注入、转正、防重复和存档读写闭环；导入导出不纳入本阶段完成标准。

## 前端命名

- 玩家可见：`红颜录`、`红颜规划`、`任务`。
- 内部协议、prompt、命令路径和存档字段：继续使用 `女主剧情规划`。
- 项目名 `墨色江湖` 未来会换，本轮不处理。
- 拿不准的新名字先问，不为文采牺牲模型协议清晰度。

## useGame 边界

- `useGame.ts` 当前仍是 composition root；行数未明显下降不是异常，而是说明本轮只完成了边界收口。
- 已抽出的 `promptRuntimeFacade`、`socialDirectorSync` 和 grouped workflow facades 是后续拆分锚点，不代表 `useGame.ts` 已完成瘦身。
- 后续若继续重构，应拆 controller/composer，而不是在 `useGame.ts` 内继续堆更多 facade 对象。
- 推荐方向：开局/session、prompt runtime、社交/导演配置、存档、后处理调度、图片 runtime 分别进入独立 controller。
- 每轮只迁一组 controller，先迁依赖边界和创建点，不顺手重写业务算法。
- Phase 3 不以完成 `useGame.ts` controller 化为 closeout 条件；只有当前功能闭环必须触及时才继续小步拆分。

## 验证原则

- 优先补 focused tests：formatter、normalization、prompt string、parser、状态判断、调度条件、save snapshot。
- 不做浏览器自动化。需要 UI smoke 时只启动服务器，由用户手动浏览器测试。
- 文档是当前状态文档，不写客户 changelog；完成项只简单记事实，未完成项写清下一步。

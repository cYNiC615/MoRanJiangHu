## 当前项目判断

这个项目应按 AI-native RPG harness 理解，而不是传统确定性 RPG 引擎。

当前核心链路是：

1. 前端维护本地游戏状态、设置、存档和 UI。
2. 世界书、提示词、记忆、角色状态、环境状态和历史对话按需进入上下文。
3. 主剧情模型输出正文、短期记忆、变量规划、剧情规划和行动选项。
4. 独立链路继续处理变量生成、世界演变、规划分析、地图更新和记忆整理。
5. 本地代码解析协议、应用命令、规范化状态、落盘到 IndexedDB 并刷新前端。

后续可以把地点、物品账务、时间、任务、对抗等高风险逻辑逐步代码化，但 AI 驱动角色扮演、上下文控制、世界书注入、prompt/schema 和状态回写仍是项目主轴。

## Homebrew 锚点

- 默认体验改为现代都市，可扩展近未来科幻；不保留武侠/修仙作为默认或兼容目标。当前默认新建一路向下仍会生成武侠世界，这是 Phase 2 高优先级未完成项。
- 不做同人、原著融合、小说分解、小说拆解后改编。
- 不做移动端、APK、多设备同步、社区 UGC、公共在线运营。
- Cloudflare 托管/AI 代理暂缓决定，等云同步、APK、社区和运营外围拆完后再评估。
- 本地设置、API 配置、本地存档、ZIP 导入导出、世界书、记忆和主聊天体验必须保留。
- 保留男性向恋爱/亲密关系和“女主”概念，但后续要优化后宫模式下的规划方式。
- 旧战斗系统废弃，未来用新的轻量级对抗系统替代。
- 天气不作为结构化游戏系统，只能作为 AI 正文氛围；节日系统删除。

## 当前阶段

当前工作处在 Phase 1 实现侧完成、用户初步测试通过、准备进入 Phase 1.5 的状态。

Phase 1 的目标是让废弃功能离开当前可玩主链路：玩家路径不可达、顶层副作用断开、active prompt/schema/命令过滤不再要求 AI 主动维护废弃状态。已废弃命令根需要被 registry 拒绝或在 apply 阶段 no-op。不可达前端文件、后端服务、模型字段、storage key 和测试可以暂留，但必须登记当前状态。

Phase 1.5 当前目标是删除不可达或误导性的前端/设置/提示词管理残骸：主页公共入口、退役提示词可见项、未挂载弹窗、旧面板、移动端组件、废弃设置页、lazy import、UI state、props、样式和前端测试。后端 API、模型字段、prompt 文件和 IndexedDB 强迁移留到后续深删阶段。

当前 Phase 1 进度：

| 工作面 | 当前状态 |
| --- | --- |
| 玩家入口 | 已明确废弃的功能族从当前桌面主流程不可达；设置下拉和世界书内置槽位也不再暴露“修炼”叙事风格 |
| 顶层副作用 | 启动、保存、回合后处理、返回主页、心跳、定时器和后台队列不再维护废弃功能 |
| AI 主动维护 | 旧战斗、玩家门派、同人规划等废弃命令根进入退役状态；主系统/酒馆上下文不再输出废弃结构化状态 |
| 当前残留 | dormant fandom branches、旧 prompt 文件、模型字段、API、storage key 和测试按当前清理队列登记，不在 Phase 1 追求全删 |
| 已知体验问题 | 默认新建仍是武侠；提示词管理仍可见境界体系/修炼相关退役提示词并可能显示“运行时注入” |
| 收口条件 | 静态测试、搜索审计、build、HTTP 预览、浏览器 smoke 和用户初步测试已通过；可以进入 Phase 1.5 |

## 后续 Phase 路线

| Phase | 当前目标 |
| --- | --- |
| Phase 1.5 | 前端/设置/提示词管理瘦身：主页公共入口、退役提示词可见项、移动端组件、旧战斗/拍卖行/小说分解前端 |
| Phase 2 | 现代都市默认化：新建默认一路向下必须进入现代都市，并同步题材、开局、世界观生成、模式包、组织/地点/货币口径 |
| Phase 3 | 后端/prompt/model/storage 深删：同人、小说分解、武侠修炼、旧战斗、拍卖行、云同步、APK、公共运营 |
| Phase 4 | 第一批代码化系统：地点移动、物品/货币/装备账务、轻量时间 |
| Phase 5 | 社交/NPC 和轻量对抗重构：NPC 位置/在场判定、关系守卫、新轻量对抗系统 |

## 当前未决问题

- PromptManager 对退役提示词采用隐藏、归档还是直接从提示词池删除，需要在 Phase 1.5 第一刀里定。
- IndexedDB 中旧 `builtin_prompt_entries` / `extra_worldbooks` 如何强迁移或重置，留到 Phase 3。
- 创意工坊是否改名为“模式包/本地扩展”，可在主页瘦身或现代都市默认化时处理。
- NPC 位置/在场判定、轻量时间、图片生成、Cloudflare 托管/AI 代理都需要后续单独设计，不阻塞 Phase 1.5。
